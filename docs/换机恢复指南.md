# 换机恢复指南（macOS）

换一台 Mac 后，按本文档恢复完整的 DSH Desktop 二次开发环境（含公司模型接入）。

> 配套文档：
> - [`本地环境同步说明.md`](./本地环境同步说明.md) —— skill 与全局规则的软链接细节
> - [`../config/settings.example.yaml`](../config/settings.example.yaml) —— 模型配置模板

## 一、恢复清单

| 要恢复的东西 | 来源 | 方式 |
|---|---|---|
| 代码（含全部二次开发） | GitHub `wentao-hu/dsh-desktop` | `git clone` |
| 依赖与补丁 | npm registry + 仓库内 `patches/` | `npm ci`（postinstall 自动打补丁） |
| 可双击的应用 | 本地构建 | `npm run package:dev:mac:arm64` |
| **环境变量** | 本文档 §三 | 手动写入 `~/.zshrc` |
| **模型路由配置** | 仓库 `config/settings.example.yaml` | 复制到 DSH_HOME 并改名 |
| skill | 你的 skills 仓库 | 软链接（见同步说明 §三） |
| 全局规则 | `~/.claude/CLAUDE.md` | 软链接（见同步说明 §三） |

**关键认知**：DSH_HOME（`~/Library/Application Support/dsh-desktop-dev/harness/`）**不在仓库里**。
其中 `settings.yaml` 必须手动恢复，**否则模型跑不起来**（会退回没有 key 的官方路由）。

## 二、环境要求

- macOS（Apple Silicon）
- Node.js 22+ 与 npm
- git，且 SSH key 已加入 GitHub

## 三、环境变量（必须，值不入库）

harness 进程启动时会**捕获登录 shell 的环境**（执行 `$SHELL -l -i -c env`），
因此变量必须写在 `~/.zshrc`，**不是**只在当前终端 `export`。

```bash
cat >> ~/.zshrc << 'EOF'

# ===== DSH Desktop 二次开发：接入公司 responses 接口 =====
export SANKUAI_API_KEY="<向管理员申请你的 AppID>"
export DSH_RESPONSES_NATIVE_TOOLS="web_search"
# ===== 结束（删除本段即可撤销）=====
EOF
```

**验证**（模拟应用读取环境的方式）：

```bash
/bin/zsh -l -i -c 'echo "key=$SANKUAI_API_KEY tools=$DSH_RESPONSES_NATIVE_TOOLS"'
```

两个值都能打印 = 配置正确。

## 四、逐步操作

### 步骤 1：拉代码

```bash
cd ~/Desktop
git clone git@github.com:wentao-hu/dsh-desktop.git
cd dsh-desktop
# 加上游 remote，供后续同步 B 的更新
git remote add upstream https://github.com/dataelement/dsh-desktop.git
git remote set-url --push upstream no_push
```

### 步骤 2：装依赖

```bash
npm ci     # postinstall 会自动应用 patches/ 下的全部补丁
```

**验证补丁已生效**（两个都应 ≥1）：

```bash
grep -c "DSH_RESPONSES_NATIVE_TOOLS" node_modules/@earendil-works/pi-ai/dist/api/openai-responses.js
grep -c "session/delete"             node_modules/@deepseek-ai/dsh-api-remotes/lib/client.js
```

### 步骤 3：配环境变量

见 §三。

### 步骤 4：恢复模型配置

```bash
H="$HOME/Library/Application Support/dsh-desktop-dev/harness"
mkdir -p "$H"
cp config/settings.example.yaml "$H/settings.yaml"
```

### 步骤 5：重建 skill 与规则软链接

```bash
bash scripts/link-skills.sh
H="$HOME/Library/Application Support/dsh-desktop-dev/harness"
ln -sfn "$HOME/.claude/CLAUDE.md" "$H/AGENTS.md"
```

（细节与原理见 `docs/本地环境同步说明.md`）

### 步骤 6：打包并启动

```bash
npm run package:dev:mac:arm64
open "dist-dev/mac-arm64/DSH Desktop Dev.app"
```

### 步骤 7：跑门禁（推荐）

```bash
npm run typecheck && npm test
```

## 六、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 界面里没有 `Sankuai AIGC` | `settings.yaml` 位置不对或 YAML 不合法 | 确认路径；用 `python3 -c "import yaml;yaml.safe_load(open(...))"` 校验 |
| 报「API 密钥无效」 | 默认模型退回 `deepseek-official`（需 DeepSeek 官方 key） | 确认 `agent-default-model.provider` 是 `sankuai` |
| 报 `Tool names must be unique` | pi-ai 补丁没应用 | 重跑 `npx patch-package` |
| 报 `sandbox escalation ... not strictly wider` | 权限预设是最高档 `danger-full-access` | 改成 `workspace-write`，详见同步说明 §八 与模板注释 |
| 看不到 skill | 软链接缺失或已成断链 | 跑 `scripts/link-skills.sh`，然后重启应用 |
| 全局规则不生效 | 文件名不对 | 必须是 `AGENTS.md`（不是 `CLAUDE.md`） |

## 七、日常同步上游（B 的更新）

```bash
cd ~/Desktop/dsh-desktop
git fetch upstream --tags
git merge upstream/main      # 冲突多出现在 patches/ 目录
git push origin main
```

另有每周一自动检查（launchd），有更新会弹系统通知 + 在桌面生成报告。
