# 本地环境同步说明：skill 与全局规则

> 适用：本仓库（DSH Desktop 二次开发版）在 macOS 上的本地部署
> 最后更新：2026-09-11

## 一、同步关系总览

DSH Desktop 从两个**固定路径**读取 skill 和全局规则。本机不往这两个路径直接放文件，
而是用**软链接**指向唯一真源，做到"只改一处，两边生效"。

| 内容 | 唯一真源（日常只改这里） | DSH Desktop 的读取路径 | 链接方式 |
|---|---|---|---|
| skill（39 个） | `~/.skills-manager/skills/<名字>/` | `~/.agents/skills/<名字>` | **逐个**软链接 |
| 全局规则 | `~/.claude/CLAUDE.md` | `$DSH_HOME/AGENTS.md` | 软链接 |

其中 `$DSH_HOME`（桌面端开发态）= `~/Library/Application Support/dsh-desktop-dev/harness/`

## 二、为什么目标路径是这两个（不是随便挑的）

| 路径 | 依据 |
|---|---|
| `~/.agents/skills` | 上游 `dsh-skill-filesystem` 的默认 skill 根之一（rank 500 / `user-agents`），且其代码**明确支持软链接**——有 `isSymbolicLink` 分支去 follow，失败才 warn 忽略 |
| `$DSH_HOME/AGENTS.md` | 上游 `dsh-agent-instructions` 里写死 `USER_GLOBAL_FILE = "AGENTS.md"`。**用户全局规则只认这个名字**；`CLAUDE.md` 是**项目级**候选名（`DEFAULT_INSTRUCTION_FILE_CANDIDATES`），不适用于用户全局这一层 |

**反面教材**：另一个同类项目（`ningbainb/deepseek-harness-desktop`）自研的 skill 扫描**拒绝软链接**，
会直接报 `skill discovery ignores symbolic links`。所以本方案只适用于本仓库所用的这套上游实现。

## 三、换电脑 / 重装后的重建步骤

### 前置：准备好两个源头

- **skill 源**：从你的 skills 仓库 clone 到 `~/.skills-manager/skills`（应含若干「目录 + `SKILL.md`」结构）
- **规则源**：`~/.claude/CLAUDE.md`

### 步骤 1：建 skill 软链接（逐个）

```bash
SRC="$HOME/.skills-manager/skills"
DST="$HOME/.agents/skills"
mkdir -p "$DST"

for d in "$SRC"/*/; do
  name=$(basename "$d")
  target="${d%/}"
  if [ -e "$DST/$name" ] || [ -L "$DST/$name" ]; then
    continue
  fi
  ln -s "$target" "$DST/$name"
done

ls -la "$DST" | grep '\->' | wc -l   # 应等于源目录数
```

> 更省事：直接跑仓库里的 `scripts/link-skills.sh`（同一逻辑，另带断链清理）。

### 步骤 2：建全局规则软链接

```bash
H="$HOME/Library/Application Support/dsh-desktop-dev/harness"
mkdir -p "$H"
ln -sfn "$HOME/.claude/CLAUDE.md" "$H/AGENTS.md"

ls -la "$H/AGENTS.md"    # 应显示 -> /Users/<你>/.claude/CLAUDE.md
```

`ln -sfn` 的 `n` 表示：目标已是链接时**直接替换链接本身**，而不是跟随进目录再建。

### 步骤 3：验证

```bash
# skill：应能读到某个 skill 的正文（前几行即可）
head -3 ~/.agents/skills/citadel/SKILL.md

# 规则：应能读到 CLAUDE.md 的正文
head -3 "$HOME/Library/Application Support/dsh-desktop-dev/harness/AGENTS.md"
```

两条都能输出内容 = 链接建立成功。

### 步骤 4：重启 DSH Desktop

文件系统层面软链接立即生效，但 **skill 目录的扫描发生在应用启动时**，重启一次最稳妥。

## 四、日常维护的边界（重要）

| 你的操作 | 是否自动生效 |
|---|---|
| 改**已有** skill 的内容（如 `citadel/SKILL.md`） | ✅ 自动（软链接指向同一份文件） |
| 改 `~/.claude/CLAUDE.md` | ✅ 自动 |
| **新增**一个 skill 目录 | ⚠️ 需跑一次脚本补链接 |
| **删除**一个 skill | ⚠️ 需跑一次脚本清断链 |
| **重命名** skill | ⚠️ 需跑一次脚本（旧的清断链 + 新的补链接） |

**一键处理**：

```bash
bash ~/Library/Application\ Support/dsh-sync/link-skills.sh
```

脚本会打印新增和清理的条目，跑完无需重启（skill 根目录被 watch）。

## 五、可选：改成"整目录链接"实现完全自动

若希望**增删 skill 也不用跑脚本**，可以让 `~/.agents/skills` 本身成为指向源目录的软链接：

```bash
# ⚠️ 前提：先确认 ~/.agents/skills 里没有其它工具依赖的独立 skill
mv ~/.agents/skills ~/.agents/skills.bak          # 先备份
ln -s "$HOME/.skills-manager/skills" ~/.agents/skills
ls ~/.agents/skills | head                         # 应直接列出源目录内容
```

**代价与风险**：`~/.agents` 是"共享 agent 配置根"，其它 agent 工具也可能读它；
改成整目录链接前，务必确认没有冲突。

## 六、故障排查

| 现象 | 排查顺序 |
|---|---|
| 界面里看不到 skill | ① `ls ~/.agents/skills` 有内容吗 → ② `ls -la` 看每个条目是否有 `->` 且未断开 → ③ 重启应用 |
| 链接指向的路径不存在（断链） | 跑 `link-skills.sh` 清理后重建 |
| 全局规则没生效 | ① 文件名必须是 `AGENTS.md`（**不是** `CLAUDE.md`）→ ② 必须在 `$DSH_HOME` 根下 → ③ `readlink` 确认指向正确 |
| 改了源文件但应用没变 | 内容类改动即时生效；若涉及 skill 增删，跑脚本并重启 |

## 七、本机相关路径速查

| 用途 | 路径 |
|---|---|
| skill 真源 | `~/.skills-manager/skills/` |
| skill 读取点 | `~/.agents/skills/` |
| 全局规则真源 | `~/.claude/CLAUDE.md` |
| 全局规则读取点 | `~/Library/Application Support/dsh-desktop-dev/harness/AGENTS.md` |
| 同步脚本 | `~/Library/Application Support/dsh-sync/link-skills.sh` |
| 应用配置（含模型路由） | `~/Library/Application Support/dsh-desktop-dev/harness/settings.yaml` |
